    call/2-how-it-works.mdPart 3 · The technology

    How Greptile works

    Every pull request, reviewed with the context of the whole codebase, tuned to the team's standards, and able to run entirely inside Capital One's network.

    • Context: a graph of functions, classes and dependencies, so each review sees how a change affects code far from the diff.
    • Learns the team: reactions and replies tune it, and within two to three weeks it stops flagging what the team ignores. Custom rules encode Capital One's own standards.
    • Deploys where risk wants it: Greptile Cloud (SOC 2 Type II, SSO/SAML, audit logs) or self-hosted on Docker or Kubernetes, including air-gapped with custom models. Works with GitHub Enterprise Server, GitLab self-managed and Bitbucket Data Center.

    Sources: Greptile docs · self-hosting. Model setup to confirm with an FDE.

    +

    An independent reviewer. The tool that writes the code shouldn't be the only one checking it. Greptile reviews Copilot, Claude Code and Windsurf output alike.
